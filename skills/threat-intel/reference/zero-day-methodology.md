## Zero-day hunter methodology

**Target selection and ecosystem reasoning.** Hunters pick targets where one bug has ecosystem-wide leverage: a library (Cetus/`integer_mate` shipped across Sui DeFi), a front-end signing tool (Safe — one compromise drained Bybit), a framework (Next.js cluster of 11 exploited CVEs), or a config pattern replicated across protocols (LayerZero single-verifier bridges). The question is not "what is this app?" but "what do 100 apps share?"

**Surface triage.** The canon remains Jason Haddix's TBHM: enumerate root domains → subdomains → live hosts → application layering (data-passing style, JS, auth model) before any testing. Standard recon stack: subfinder/amass → httpx → waybackurls → JS extraction.

**Version/patch diffing (1-day → fresh 0-day).** Workflow: find CVE → obtain vulnerable and patched artifacts → diff → understand the fix → derive the bug → look for the same pattern in unpatched siblings/variants → PoC. This is documented as the standard n-day development loop ([r4.dk n-day workflow](https://blog.r4.dk/posts/ndaydev/), [CVE North Stars patch-diffing guide](https://cve-north-stars.github.io/docs/Patch-Diffing)). Project Zero's 0days-in-the-wild root-cause database exists specifically so researchers can learn attacker variant patterns and hunt "déjà vu" bugs — the same root cause recurring because only the symptom got patched.

**Reading shipped JavaScript, source maps, minified bundles.** Highest-yield web skill: pull all JS from the target (Burp spider, waybackurls, grep `.js`), grep for endpoints, secrets, API keys, internal hostnames; if `.map` files are exposed, reconstruct full original source with `shuji`/`source-map-explorer`. Nuclei exposures templates scale the same grep across hundreds of files.

**Auth-flow analysis as highest-yield surface.** XBOW's autonomous submissions — 1,060+ vulnerabilities to reach #1 on HackerOne's US leaderboard — skewed to XSS, SQLi, and authentication/logic flaws, i.e., session/scope/authorization reasoning, not memory bugs. Q2 2026 KEV CWEs confirm: improper authentication (CWE-287), missing auth (CWE-306), improper access control (CWE-284) = 14 of top 30 exploited entries. Method: map every token/session/OAuth-scope transition; test cross-tenant and stale-token acceptance.

**Fuzzing strategy.** Decide what to fuzz from the diff and the bug class, not from a scanner: build harnesses around newly patched functions; sanitizer choice (ASan for memory corruption, MSan for uninitialized reads, UBSan for integer overflow — the exact Cetus class); OSS-Fuzz provides the industrial template: 13,000+ vulnerabilities across 1,000 projects as of May 2025, with LLM-generated fuzz drivers adding 0–31% coverage. Triage at scale is the bottleneck — agentic crash validation now cuts reported crashes 57–61% by removing false positives. For smart contracts: fuzz at extreme parameter boundaries — Cetus/KyberSwap-class overflows live at tick/shift boundaries that normal test ranges never hit.

**Variant analysis after a new bug class lands.** When IngressNightmare, ToolShell, React2Shell, or a Balancer vault bug drops: diff all forks (27 protocols forked Balancer's code), all users of the affected library, all deployments of the same framework version. The Naptime→Big Sleep line made this the explicit methodology: "this was a previous bug; there is probably another similar one somewhere."

**Verification and PoC discipline.** Hypothesis-led experiments; PoC that demonstrates impact without collateral damage; reproducible from version-pinned artifacts; report only what you can re-run. This mirrors how Naptime was designed: mimic the researcher's iterative hypothesis-testing loop with tools (code browser, Python, debugger, reporter) rather than one-shot prediction.

**Hunter automation structure (public playbooks).** Recon pipeline running continuously (subfinder → httpx → archive crawl → JS inventory diff); watch triggers: GitHub advisories watch on dependency names in target stacks, nuclei-templates daily diff, KEV daily diff, RSS on vendor PSIRTs/ZDI/SSD; diff alerts on any target JS bundle change (bundle hash monitoring = front-end compromise detection — the control whose absence enabled Bybit). Canon reading list: Project Zero blog + 0days-in-the-wild RCAs, TBHM, ZDI, SSD Secure Disclosure, securitylab.github.com, rekt, SlowMist Hacked, Immunefi disclosures, and post-mortem series from Cyfrin, Halborn, OpenZeppelin, quillaudits.
